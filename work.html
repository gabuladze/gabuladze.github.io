Chiliz Chain

Chiliz Chain is a layer 1 public blockchain. I work in Go on the client software, a fork of Geth, and on the hard forks it ships. A hard fork is a network upgrade every node operator has to adopt at the same block height, so there is no gradual rollout and no cheap rollback.

This is continuous work rather than a project with an end date. Areas have included the rules governing token issuance and the mechanics of how validators get paid.

Health monitoring for the chain's validators

Chiliz Chain has 13 validators. Chiliz runs two of them. Partners run the other eleven. That is the problem in one line: Chiliz is accountable for the health of a network it mostly does not operate, and it had no direct way to see inside it.

I built an OpenTelemetry exporter that pushes node metrics into Datadog, and the dashboards the team reads them on. Validators are the nodes that produce blocks and they are a subset of the nodes on the chain, so this covers more machines than those thirteen.

Staking smart contract

I designed and built the staking contract used at Socios.com and Peppercoin, in Solidity. It holds over $2M of user funds and has had no security incidents.

Smart contracts are unusual to work on because deployment is close to permanent. You cannot patch one the way you patch a service. So most of the effort went into settling what the contract had to guarantee before much of it was written.

Fireblocks MPC signing

I integrated Fireblocks MPC signing into the blockchain service layer behind Socios.com. MPC signing splits a private key into shares held by separate parties, so no single machine ever holds the whole key. Good for custody. Not free in latency.

The latency showed up at peak hours. The signing service ran on a cycle of roughly 300 milliseconds and handled one request per cycle, so a single slow request blocked everything queued behind it. Head-of-line blocking, in a queue whose head moves three times a second. I changed it to handle three requests per cycle.

As far as I know, the service is no longer used in production.

Chiliz Bridge

Chiliz runs a two-way bridge that moves CHZ between Chiliz Chain and Ethereum. I built it by forking ChainBridge and modifying it. Forking rather than starting over was the point: bridges are a favourite target, and a codebase that has already survived contact with production is hard to reproduce on a deadline.

Later I cut its transaction fees by about 15%. The relayers, the processes that watch one chain and submit the matching transaction on the other, were paying a flat gas price on everything. I moved them to EIP-1559, which prices gas against current demand, so the bridge stops overpaying when the network is quiet.

Bridge monitoring platform

The operations team needed to answer "where is my transfer" without asking an engineer. I built them a platform for it. A TypeScript indexer follows both sides of the bridge and records what it sees; a REST API sits on top; a React dashboard shows every transfer and where it currently is.

Cross-chain token deployment

I have deployed more than 60 tokens across Chiliz Chain, Base, Solana and Robinhood Chain using LayerZero, which lets one token exist on several chains and move between them.

The more useful half of that was making myself unnecessary. Each deployment is a long sequence of steps that has to happen in order and in the right places, and doing it by hand meant it could only happen when I was free. I built CLI tooling that wraps the whole sequence so people outside the team can run a deployment themselves. It took about five days, working with Claude Code.

Crypto payment platform

I built and ran the crypto payment platform, on Node.js and Express. It processed transactions across Bitcoin, Ethereum, Ripple, Stellar and Tron. Each of those has its own idea of what a transaction is, when it counts as final, and how it can fail. The platform's job was to hide all of that behind one API.

Stuck withdrawals, handled automatically

A withdrawal gets stuck when it goes out with a fee the network no longer thinks is worth mining. It just sits there. Someone had to notice, find it, and resend it by hand.

I ended that. Withdrawals resend themselves now, with fees that adjust to what the network is charging at the time. The manual work went to zero.

Cheaper Bitcoin transactions

A Bitcoin fee depends on how large the transaction is in bytes, and that depends on how many earlier payments you pull in to fund it. I reworked how we chose those inputs and arranged the outputs, which brought our fees down.

Internal operations dashboard

Managers needed to see payments without going through an engineer. I built the dashboard they used daily, in Node.js, to track transactions across all of those networks and dig into the ones that failed or got stuck. It covered payments running through outside providers too, so it was the one place to look instead of one of several.

Wenu

Wenu is contactless ordering for restaurants. Scan a QR code at the table, browse the menu on your phone, order and pay from it. I built the backend and the API the mobile and web clients ran on.

It arrived at the right moment. Reusable paper menus were banned in Georgia for part of the pandemic. Wenu won a ₾100,000 GITA grant and reached more than 3,500 users across five restaurants.
